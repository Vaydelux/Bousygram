# Bousygram – Reopened implementation audit (2026-11-05)

Scope: Android playback lifecycle, Media3/libmpv, TDLib range streaming,
account invalidation, forum paging, poster generation, subtitles, Extras
networking, CI and device qualification. This is a living source audit:
**no claim that 266 source files or physical devices have all been manually
validated line by line**; autogenerated TDLib bindings require a separate
native ABI compatibility gate.

## Confirmed defects and corrections on main

1. **Native EOF confusion**: libmpv `END_FILE` can also mean stop/reload.
   Require observed EOF before treating the event as natural completion.
2. **Audio-focus reentry**: repeated Ready triggered duplicate focus requests.
   Use an idempotent controller with a focus-loss policy and explicit user-pause guard.
3. **TDLib DataSource failed open**: validation errors occurred outside cleanup.
   Ensure unauthorized, invalid and preflight failures clear partial state.
4. **Audio/subtitle track identity**: duplicate Media3 group-local IDs and
   disabled subtitle type after Off prevented reliable track re-selection.
5. **TS thumbnails**: TDLib chunk reads can complete partially before reaching
   the 2 MiB local-head prefix threshold. For focused TS cards, use bounded
   incremental low-priority prefetch only while playback is idle.
6. **Focus prefetch race**: a coroutine could complete before being inserted in
   the active-job map; an old canceled job could also remove a replacement.
   Register lazily with putIfAbsent and identity-based cleanup.
7. **Forum refresh**: refreshing the topic directory must not also start
   an unrelated whole-chat media query.

## Deferred evidence / known limitations

- An unindexed MPEG-TS file may genuinely be unseekable until an index or
  full-file demux pass is available. No byte-per-second estimate can be safely
  called frame-accurate seek. Do not report the requested timestamp as achieved.
- TS preview frames are opportunistic and can be unavailable when the prefix
  contains no decodable keyframe. Never force whole-file downloading solely
  to draw thumbnails.
- Seek overlays remain timestamp-first for remote Telegram streams. Local
  cached files can provide decoded frames; per-10-second network thumbnail
  extraction is intentionally not enabled on low-memory TVs.
- Subtitle color/size customization applies to text; embedded PGS/VobSub and
  video-burned subtitles cannot be recolored.
- Multiple TDLib scheduler maps remain process-lifetime. Do not introduce
  arbitrary map caps before measuring retained bytes/PSS and protecting active
  file leases, stream tokens, account scoping and offline pins.

## Minimum acceptance gates

- **Exactly matching main SHA**: Gradle compile/test/lint and native ABI APK
  matrix must be green. Canceled intermediate workflows prove nothing.
- **Emulator smoke**: cold launch, navigation, D-pad, captions and controls.
  Emulator does not prove 32-bit ARM media decoders or authenticated Telegram IO.
- **Physical ARM32 TV / ARM64 phone**: MKV, MPEG-TS (indexed and unindexed),
  MP4 and WebM; at least 20 seeks in both directions; manual pause through
  buffering; reconnect; app restart; subtitle tracks Off/on; cache/thumbnail
  behavior and PSS over 30–60 minute sessions.
- Keep Telegram credentials/media/logs private. Device recordings must redact
  account IDs and media titles.

**Release policy:** a debug APK is a device-test candidate, not enterprise
production readiness. Do not promise defect-free playback or label unsupported
native seek behavior as resolved.
