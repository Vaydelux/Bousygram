## 2. Bousygram's Authentic Design Identity (What "Good" Looks Like Here)

1. **Artwork and playback own the screen; chrome recedes.**
   Bousygram is a local-first Telegram video explorer and media player (plus isolated Extras catalogs). Video thumbnails, movie/TV/anime posters, and active video playback already bring rich color and motion. App chrome must stay **quiet, matte/opaque-tonal, and structurally calm**—never competing with media through glowing backdrops, rainbow borders, or gradient buttons.
2. **One brand focal point: the approved Chow Chow mascot.**
   `brand/bousygram-mascot.webp` (`R.drawable.ic_bousygram_mascot`) already contains the orange Chow Chow, the cyan-to-blue circular halo, and the white Telegram paper plane. Because the artwork itself carries the halo, surrounding UI chrome does **not** need extra radial halos, cyan neon borders, or glowing gradient dashes to signal "brand."
3. **Content above the fold on constrained viewports.**
   On `960x540dp` Android TVs (`TvStandard` / `TvCompact`) and short landscape phones (`effectiveHeightDp < 480.dp`), every vertical dp spent on decorative eyebrows, marketing taglines, or redundant headers steals a row of playable videos. Compress chrome ruthlessly; let grids and media start high.
4. **Unmistakable, low-noise state separation.**
   At 10 feet on a TV remote and at arm's length on a phone, users must distinguish four states instantly without decorative effects:
   - **Resting**: quiet tonal surface (`surfaceContainerLow` / `surfaceContainer`), no glowing outline.
   - **Selected**: semantic tonal container (`primaryContainer` / `onPrimaryContainer` or `secondaryContainer`).
   - **Focused (D-pad / keyboard)**: crisp `3.dp` `BousygramUiTokens.tvFocusOutline` ring + restrained `1.018f` scale (respecting `BousygramMotionPolicy`).
   - **Disabled / Watched**: muted contrast without breaking legibility or focus visibility.
5. **Real-estate adaptation only—never CPU ABI.**
   Drive all spacing, column count, control height, and typography scaling from `AdaptiveMetrics` and `LocalBousygramDisplaySpec` (`DeviceProfile.kt`), never `Build.SUPPORTED_ABIS`.

## 4. The Bousygram AI-Slop Kill List (9 Codebase-Specific Rules)

Apply every rule below when cleaning existing files (Mode A) or writing new UI (Mode B).

### Rule 1 — Calm the Default Backdrop; Ban Ambient Glow Blobs
- **Current slop in codebase**: `PremiumGridBackdrop.kt` (`BousygramBackdropPattern.AMBIENT_HALO`) stacks **three** large radial gradient blobs (`primaryGlow`, `secondaryGlow`, `warmAccent`) behind every screen, washing out dark-theme depth and muddying light themes. Several other composables (`NoResultsIllustration`, `BousygramBrandMark`, `PosterFallback`) stack additional radial/linear gradients on top.
- **Required fix**:
  - Keep all 7 `BousygramBackdropPattern` enum values, IDs, and `BousygramBackdropPreviewCanvas` working for users who opt into patterned backdrops.
  - Make the default `AMBIENT_HALO` backdrop **whisper-quiet**: render clean `colors.background` with at most one subtle, low-alpha tonal top falloff (`<= 0.05f` dark / `<= 0.03f` light) so surfaces stay crisp and artwork pops.
  - Never add ambient radial glow blobs inside cards, panels, dialogs, or empty-state illustrations. Keep `HIGH_CONTRAST` 100% flat.

### Rule 2 — Stop Halo-on-Halo Mascot Wrapping & Duplicate Branding
- **Current slop in codebase**: `BousygramBrandMark.kt` (`showHalo = true`) wraps the circular Chow Chow mascot—which **already has a painted cyan-blue circular halo**—inside a *second* `Brush.radialGradient` glow + a 3-color `Brush.linearGradient` border ring (`haloStart` → `haloEnd` → `goldAccent`). Callers pass `showHalo = true` everywhere (`TvTopNavBar`, `PhoneTopBar`, `TabletNavRail`, `TelegramExplorerCompactHeader`, `ModeSelectionScreen`, `AuthScreen`, `SettingsScreen`, `AboutScreen`).
- **Required fix**:
  - Default `BousygramBrandMark` to `showHalo = false` in app bars, compact headers, and interior screens; when `showHalo = true` is explicitly used on a focal hero (e.g., `ModeSelectionScreen`), replace the neon radial glow + tri-color border with clean circular framing or a subtle `1.dp` `outlineVariant` edge at most.
  - Never display `BousygramBrandMark` + `"Bousygram"` inside a screen's content column when the enclosing shell (`TvTopNavBar`, `PhoneTopBar`, or `TabletNavRail`) already displays the brand mark.

### Rule 3 — Kill Gradient-Dash + ALL-CAPS Eyebrow Heading Stacks
- **Current slop in codebase**: `BousygramPageHeading` in `BousygramDesignComponents.kt` draws a `24.dp x 3.dp` cyan-to-blue `Brush.horizontalGradient` bar next to a Lucide icon + ALL-CAPS tracked (`0.7.sp`) eyebrow (`"TELEGRAM MEDIA"`, `"TELEGRAM MEDIA  /  YOUR COLLECTION"`, `"BOUSYGRAM  /  PREFERENCES"`, `"BOUSYGRAM  /  SYSTEM & ATTRIBUTION"`), stacked above a bold `headlineLarge` title and a separate subtitle—burning vertical height and screaming generic AI SaaS template.
- **Required fix**:
  - Remove the decorative `24x3dp` gradient pill dash and ALL-CAPS breadcrumb kickers from `BousygramPageHeading` (keep its signature source-compatible if callers pass `eyebrow`, rendering quiet sentence-case context only when genuinely informative, never repeating the screen title or `"Bousygram / ..."`).
  - Prefer `BousygramCompactPageTitle` or a clean 1–2 line title + muted inline status (`onSurfaceVariant`) across `TelegramHomeOverview`, `FavoritesScreen`, `SettingsScreen`, `AboutScreen`, and `TvVideoSearchScreen` so playable content starts immediately.

### Rule 4 — Enforce a Strict Max-2-Overlay Budget on Media Cards
- **Current slop in codebase**: `MediaPosterCard` in `EnterpriseComponents.kt` can stack up to **six** overlays on a single 16:9 thumbnail simultaneously: top-left `GlassPill` (`Watched` / `TS` / `FAVORITE`), top-right `MediaActionsDropdown`, bottom-left `GlassPill` (`"Resume 42%"`), bottom-right `GlassPill` (duration), `76.dp` vertical gradient scrim, centered gradient-circle `CenteredPlayBadge` on focus, and a `3.5.dp` bottom `LinearProgressIndicator`. Meanwhile, `PosterFallback` renders a 3-stop cyan gradient, a bordered circle, and `"Telegram Video"` text.
- **Required fix**:
  - **Max 2 visual overlays on a resting thumbnail**: (1) one compact, opaque high-contrast corner metadata chip (duration—or single status when duration is absent) and (2) the slim bottom progress bar when partially watched.
  - Remove the redundant `"Resume XX%"` `GlassPill` whenever the bottom progress bar is already rendered (keep progress info in TalkBack `semantics`).
  - Keep `GlassPill` restrained: use flat, opaque dark/surface-tonal fills (`colors.surfaceContainerHighest` / dark scrim) with clean corners instead of glowing colored borders (`haloStart.copy(alpha = 0.70f)`).
  - Simplify `CenteredPlayBadge` on focus (solid, crisp play glyph without a `Brush.linearGradient` circle + semi-transparent white border—or rely on the card's `3.dp` focus ring so artwork stays unobstructed).
  - Calm `PosterFallback` down to a solid `colors.surfaceContainerHigh` surface with a single understated `BousygramIcons.Film` / `PrivacyHidden` icon—no multi-stop cyan gradient, no bordered badge circle, no `"Telegram Video"` filler text.

### Rule 5 — Stop Triple-Bordered Translucent "Glass" Nesting
- **Current slop in codebase**: `EnterprisePanel` (`EnterpriseComponents.kt`), `TvFocusSurface`, `AuthScreen`, `AboutScreen`, and `CinematicPlayerChrome` layer translucent `alpha = 0.90f` fills + `halo.glassBorder` (`brandCyan.copy(alpha = 0.24f)`) borders on static containers, then nest bordered `Surface` cards, bordered `BousygramButton`s, and bordered `GlassPill`s inside them. In `CinematicPlayerChrome`, a bordered `hudSurface` dock sits *on top of* an `182.dp` vertical gradient scrim.
- **Required fix**:
  - Use **Material 3 tonal surface hierarchy** (`background` → `surfaceContainerLow` → `surfaceContainer` → `surfaceContainerHigh`) to separate sections instead of drawing `1.dp` cyan borders around every resting container.
  - Reserve visible outlines for:
    1. **D-pad / keyboard focus** (`BousygramUiTokens.tvFocusOutline = 3.dp` in `colors.primary`),
    2. **Selected state** (`1.5.dp` or tonal `primaryContainer` fill),
    3. **High Contrast mode** (`1–1.5.dp` `outline` / `outlineVariant`), and
    4. **Interactive style overrides** explicitly requested by `IPHONE_GLASS` / `COZY_KAWAII` `BousygramStyleSpec`.
  - In `CinematicPlayerChrome`, keep player HUD controls clean and compact over video without double-framing heavy bordered boxes on top of tall gradient scrims; preserve exact `playerHudSurfaceOpacity` values, `48dp`/`56dp` targets, and scrim readability over bright video frames.

### Rule 6 — Ban Tooltip Spam on Already-Labeled Controls
- **Current slop in codebase**: `BousygramTooltipBox` (`BousygramTooltip.kt`) wraps buttons, tabs, and cards that **already display clear visible text labels** (`BousygramButton`, `TvTopNavBar` tabs `"Home"`/`"Library"`/`"Search"`, `ModeOption`, `BousygramThemeGallery`, `BousygramDesignStyleGallery`, `BousygramBackdropGallery`, `AboutScreen` `"Back"` button). Moving a TV D-pad or tapping controls constantly spawns floating dark popups with cyan borders that cover neighboring rows and merely repeat the label.
- **Required fix**:
  - **Tooltips are strictly for icon-only controls** (`BousygramIconButton`, icon-only `CinemaHudButton`, and `BousygramSectionTab` when `iconOnly == true`) or genuinely truncated overflow controls where the user cannot read the action otherwise.
  - Remove redundant `tooltip` arguments from visibly labeled `BousygramButton`s, labeled `TvTopNavBar` tabs, `ModeOption` cards, and labeled picker cards while keeping full `contentDescription` / `semantics` intact for TalkBack.

### Rule 7 — Replace Glowing Canvas Clipart with Calm Empty/Error States
- **Current slop in codebase**: `NoResultsIllustration` in `EnterpriseComponents.kt` draws a `96.dp` custom `Canvas` with a radial glow aura, film slate, sprocket dots, and magnifying glass with an `"X"`. Both `NoSearchResultsEmptyState` and `EmptyStateView` wrap centered text inside heavy bordered `EnterprisePanel` boxes.
- **Required fix**:
  - Replace custom glowing Canvas clipart with quiet, scannable typographic empty/error states using a single `BousygramIcons` vector icon (`BousygramCenteredStatus` or `StreamingStatusPanel`) + concise explanation + direct recovery button (`Clear search`, `Retry`, `Refresh`).
  - Keep `no_results_empty_state`, `no_results_title`, `no_results_message`, `bousygram-empty-state*` test tags intact so existing search/empty-state tests stay green.

### Rule 8 — Purge AI Marketing Copy, Buzzwords, Pulsing Dots & Duplicate Chrome
- **Current slop in codebase**:
  - `AboutScreen.kt`: Inconsistent casing `"BousyGram"` (should be `"Bousygram"`), `"Bousygram  /  System & Attribution"` + `"About BousyGram"` + `"System Information & Attribution"` repeating the same phrase 3 times, `"Zero-Configuration Video-First Telegram Client..."`, a `"Zero-Configuration Philosophy"` brochure card, a 4-chip `"Engine & Platform Foundation"` spec-sheet (`TDLib Native C++`, `Media3 ExoPlayer`, `libmpv`, `Ktor HTTP Loopback`), and **two** separate Back buttons (`"Back"` at top + `"Return to Previous Screen"` at bottom).
  - `ModeSelectionScreen.kt`: Cliché tagline `"Your screen. Your library."`, filler subtitle `"Choose a media experience to get started."`, and `"More to Explore"` on `ExtrasMaintenanceScreen`.
  - `AuthScreen.kt`: Infinite pulsing status dot (`rememberInfiniteTransition` alpha animation on a dot inside a bordered status pill) and verbose `"Enterprise-grade, modern..."` framing.
  - `TelegramHomeOverview.kt`: Repeats Search and Settings icon buttons inside the Home screen body even when `TvTopNavBar` / `PhoneTopBar` / `GlassBottomBar` already provides Search and Settings/Me.
- **Required fix**:
  - Normalize brand name everywhere to **`Bousygram`** (never `BousyGram`).
  - Write **short, literal, utility-grade copy**: state what a screen or button does in plain words. No marketing slogans, no `"Zero-Configuration Philosophy"` essays, no internal tech-stack bragging (`Ktor HTTP Loopback`, `TDLib Native C++`) on user-facing screens. Keep app version + concise privacy/storage summary + the mandatory TMDB legal attribution in `AboutScreen.kt`.
  - Remove decorative infinite pulse animations (`AuthScreen` status dot) in favor of a calm static status indicator (and `BousygramInlineStatus` for errors/offline states).
  - Eliminate duplicate Back buttons (`AboutScreen`) and duplicate top-level nav shortcuts when the enclosing `BousygramAdaptiveShell` already owns them—without removing any action required by `TelegramHomeOverviewInstrumentedTest` or standalone screen entry points.

### Rule 9 — Refine Typography Execution & Consolidate Fragmented Primitives
- **Current slop in codebase**:
  - `BousygramTheme.kt` applies aggressive negative tracking (`-1.6.sp` on `displayLarge`, `-1.2.sp` on `displayMedium`), mixes `FontWeight.ExtraBold` (`AuthScreen`), and lacks consistent typographic restraint across cards vs headers.

    - Moderate display negative tracking (`-0.5.sp` to `-0.8.sp` max) for legibility on 720p/1080p TV panels.
    - Cap weights to `Normal`, `Medium`, `SemiBold`, and `Bold` (no `ExtraBold`).
    - Apply `.tabular()` to every timestamp, duration, file size, episode counter, and badge count.
    - Respect `displaySpec.maxReadingWidth` on text-heavy screens (`SettingsScreen`, `AboutScreen`, `AuthScreen`).
  - Consolidate screen controls onto shared Bousygram primitives (`BousygramButton`, `TvFocusSurface`, `BousygramSectionTab`, `BousygramInlineStatus`, `BousygramCenteredStatus`, `StreamingVisualTokens`) so `ExtrasSpotlightCard`, `ExtrasCatalogScreen`, `AuthScreen`, and Telegram screens share identical focus rings, heights, surface tones, and corner geometry.
  - Do **not** introduce new ad-hoc tokens in `BousygramHaloColors`; route new UI styling through `MaterialTheme.colorScheme` or `StreamingVisualTokens`.

Follow `docs/agent/REVIEW_PROTOCOL.md` and `docs/agent/QA_MATRIX.md`. Run exact commands when the build environment is available, and mark any unexecuted device/emulator step explicitly as **`NOT RUN`**—never claim visual or TV verification from JVM compilation alone.

```bash
# 1. Brand identity & Telegram-local boundary checks (same scripts run by android-enterprise.yml)
bash tools/ci/verify_brand_identity.sh
bash tools/ci/verify_telegram_local_only.sh

# 2. TV hardening, Kotlin compile, lint, unit tests (contrast, metrics, motion, tokens), debug & androidTest APKs
./gradlew --no-daemon --console=plain \
  :app:verifyTvHardeningContract \
  :app:compileDebugKotlin \
  :app:lintDebug \
  :app:testDebugUnitTest \
  :app:assembleDebug \
  :app:assembleDebugAndroidTest
```

When an emulator is available, run the targeted Compose UI suites covering changed surfaces:
- `BousygramThemeGalleryInstrumentedTest`
- `UniformPremiumDesignInstrumentedTest`
- `ModeSelectionInstrumentedTest`
- `TelegramLibraryDesignInstrumentedTest`
- `TelegramHomeOverviewInstrumentedTest`
- `TelegramExplorerCompactHeaderInstrumentedTest`
- `CinematicPlayerChromeInstrumentedTest`
- `CinematicScrubberInstrumentedTest`
- `ExtrasVisualConsistencyInstrumentedTest`
- `ExtrasDpadFocusInstrumentedTest`
- `TvFocusIndicatorInstrumentedTest`

Inspect real before/after screenshots across Midnight, Daylight, and High Contrast—and explicitly flag physical ARMv7/ARM64 Android TV, tablet, and phone QA as **manual QA required / NOT RUN** until actually executed on hardware.
